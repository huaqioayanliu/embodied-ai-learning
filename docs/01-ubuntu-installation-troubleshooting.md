# 从 Windows 到 Ubuntu：安装与环境搭建中的问题记录

整理日期：2026 年 10 月 15 日

为了学习 MuJoCo 和机器人控制，我在保留 Windows 的基础上安装了 Ubuntu。真正开始操作后发现，除了安装系统本身，还需要处理磁盘分区、校园网、软件源、中文输入法，以及 Python 环境与编辑器之间的关系。

这篇文章记录自己遇到的问题、当时的处理结果和理解。完整的环境信息与日常启动命令见[Ubuntu 与 MuJoCo 环境配置记录](01-ubuntu-mujoco-setup.md)。

## 1. 安装前：分区会不会影响原来的 Windows？

一开始最关心的是，给 Ubuntu 分配空间后，Windows 中的游戏、Anaconda 和原来的虚拟环境会不会受到影响。

这次从内部磁盘中划出了约 500 GB 未分配空间用于安装 Ubuntu，并保留 Windows。

我对这一步的理解是：压缩已有分区、获得未分配空间，与删除或格式化已有分区是不同操作。实际安装时，要根据磁盘容量、型号与已有分区确认目标。

结果：已进入 Ubuntu，后续主要在 Ubuntu 中学习和开发，Windows 继续保留。

## 华硕天选 6 的 BIOS 设置

我使用的笔记本是**华硕天选 6**。开机出现华硕天选图标时，连续按几次 **F2**，就可以进入 BIOS 界面。

安装过程中，我在 BIOS 中关闭了以下选项：

- 快速启动（Fast Boot）
- 安全启动（Secure Boot）
- VMD Controller
- Armoury Crate 控制接口支持

安装完成后，我又进入 BIOS，将之前修改的设置调回。这是我这次安装时采用的操作，具体设置需要结合自己的硬件和系统配置判断，尤其要记住修改前的状态，避免影响 Windows 启动。

## 我遇到的 Windows PIN 失效问题

安装前，还有一件事值得提前留意：**Windows 的登录方式，以及自己是否记得账户密码。**

我的个人建议是，安装前先检查是否能够使用账户密码登录，再考虑临时关闭 PIN 登录。因为安装过程中如果遇到问题、需要返回 Windows，可能会碰到 PIN 失效，要求重新设置 PIN，并联网验证身份的情况。

我当时就遇到了这个问题。

如果你也在学校，电脑插着的校园网需要先打开网页进行身份认证，那么到了 Windows 登录界面，就可能无法完成这一步。我当时插着网线，也尝试连接自己的手机热点，但在重新设置 PIN、进行联网验证时，仍然提示没有网络连接。这时你可能需要拔掉网线。

反复尝试期间，我的 Windows 登录账户还被锁了，因为短时间内多次进行验证。

## 最后采用的解决办法

如果你已经遇到类似问题，可以参考这位 CSDN 博主的文章：

[Windows 登录问题解决参考](https://blog.csdn.net/lxlyhwl/article/details/145684494)

我最后就是按照这篇文章中的方法解决的，个人感觉很有帮助。

**需要特别注意：我使用这个办法时，需要的是 Windows 账户密码，不是 PIN 码。** 这两者不是同一个东西，安装前最好先确认自己记得账户密码。

## 4. 网络：ubuntu系统中连上校园网，却没有弹出认证页面

进入 Ubuntu 后，遇到过校园网认证页面没有自动跳转的问题。校园网还涉及零信任客户端，网络访问与普通家庭网络不完全一样。

后续已确认网络可以使用，也进行过网络连通性测试。不过，认证恢复的完整操作没有保留下来，因此这里只记录问题与结果。

配置软件源时也出现过访问受阻的情况。这让我意识到，下载失败不能只根据最后一行报错判断：网络认证、代理或零信任状态，以及下载目标本身，都可能影响结果。

结果：网络恢复可用；没有足够记录将所有下载问题归因于同一个原因。

## 5. 软件源：安装失败，不一定是安装包的问题

配置过程中使用过镜像源，也遇到过华为云镜像索引文件尺寸不匹配的情况。该问题出现在安装软件的过程中，容易被误认为是某个软件本身无法安装。

当时的记录指向软件源索引或同步问题，之后对软件源进行了修复。本文不还原未完整保留的换源命令。

这次比较重要的认识是，要区分三套来源：

| 工具 | 主要管理对象 |
| --- | --- |
| apt | Ubuntu 系统软件包 |
| conda | Conda 环境中的包 |
| pip | 对应 Python 环境中的 Python 包 |

修改 apt 的镜像，不代表 conda 和 pip 的来源也一起改变。排查时应先看清失败的是哪个命令、访问的是哪个地址。

## 7. swap：设置了 16 GB，为什么显示约 15 GiB？

电脑物理内存为 16 GB。这次将原有约 4 GB 的 swap 调整为 16 GB，并配置开机启用。历史查询中显示约 15 GiB。

GB 和 GiB 使用的计量方式不同，不能只凭这两个数字的差别就判断设置失败。

我也开始区分物理内存与 swap：swap 使用磁盘空间，能够在部分情况下缓解内存不足，但性能不能等同于增加相同容量的物理内存。

详细配置和查询方式放在上一篇笔记中，这里保留当时的疑问与处理结果。

## 8. Linux 软件应该安装到哪里？

刚开始仍习惯 Windows 的方式，想为每一个软件手动建一个安装文件夹。

后来的理解是，使用系统包管理器安装的软件通常由包管理器组织文件；自己需要重点管理的是项目代码、模型、数据和笔记。

Conda 环境也与项目目录不同。环境保存 Python 和依赖，项目目录保存自己写的代码和相关资源。打开项目文件夹，并不意味着已经选中了对应的 Python 环境。

## 9. QQ 音乐：安装完成后打开闪退

安装 Linux 版 QQ 音乐后，出现了打开程序就闪退的现象。相比之下，当时 VS Code 运行正常。

在终端使用以下命令后，已确认 QQ 音乐能够启动：

```bash
qqmusic --no-sandbox --disable-gpu
```

这两个参数同时改变了沙箱和 GPU 相关启动行为。因为没有分别测试单个参数，所以目前只能确认组合有效，不能据此确定究竟是哪一项导致闪退。

其中 --no-sandbox 会关闭应用相关的沙箱保护，因此这里只将这条命令作为当时的临时处理记录，不能视为所有应用的通用修复方法。

之后还讨论过桌面启动器中的 Exec 项，以及末尾的 %U。%U 是桌面启动器用于传递 URL 参数的占位符，不是要原样输入终端的参数。

目前记录能确认的是“终端命令启动成功”；桌面图标启动是否最终修复，还需要补充实际验证结果。
